# weflow-chat 实施计划

## 目标

从已验证的私人刷新工具中精选迁移必要实现，建立无私人路径、无真实数据、无内存密钥扫描且可通过一条 PowerShell 命令安装的 Windows x64 源码可见项目。

## 成功门禁

- 每项改动都由合成测试或静态门禁验证。
- 未知微信或 WeFlow 版本的正式写入计数必须为零。
- 刷新核心不得导入或调用进程内存读取、首次密钥恢复或网络客户端。
- 工作树和完整 Git 历史不得出现真实用户目录、账号 ID、固定私人盘符、运行记录、聊天数据、密钥或令牌。
- 最终 Python、Node、PowerShell、合成端到端、安装包和隐私扫描全部通过。

## 任务 1：建立公开仓库骨架与隐私门禁

创建项目元数据、严格 `.gitignore`、`.gitattributes`、公开文件允许清单和 `tools/privacy_scan.py`。隐私扫描必须检查工作树中的已跟踪候选、Git 索引和全部提交内容；规则覆盖个人路径、账号 ID、历史 UUID、数据库/媒体/日志扩展名、高熵凭据与禁止模块名。

验证：使用安全合成夹具应通过；注入每类禁止字符串或文件名时应失败；当前仓库扫描应为零发现。

## 任务 2：精选迁移纯刷新核心

按显式文件清单迁移原子 IO、路径边界、清单、复制、配置事务、恢复、安全、VSS、兼容性、验证器和刷新状态机。只迁移当前工作树中已经通过回归测试的内容，不迁移原 Git 历史、私人文档、诊断脚本、缓存或构建产物。

验证：迁移后的纯单元测试先在合成路径运行；与主机无关的 Python、Node 和 PowerShell 测试结果不得因迁移改变。

## 任务 3：移除首次密钥与进程内存扫描能力

不迁移 `key_recovery.py`、`safe_storage.py` 和 `tests/key_recovery`。从验证器删除连接失败后的内存扫描重试、恢复信封状态和 `READ_ONLY_KEY_RECOVERY` 写入能力。公开版只接受 WeFlow 已有 `safe:` 信封；缺失或失效时返回固定只读错误。

验证：依赖图、源码文本和字节码扫描均不得出现 `OpenProcess`、`ReadProcessMemory`、内存扫描入口或被排除模块导入；已有信封合成验证通过，缺失信封正式写入为零。

## 任务 4：实现通用主机合同与发现

用不可变 `HostContract` 实例替代默认单机常量。新增 `host_discovery.py`，通过 Windows Known Folder、安装记录、规范路径、普通文件/reparse 检查和签名身份发现 WeFlow 与 Weixin。账号发现从 WeFlow 配置取得选择器，再匹配结构合法的 Weixin 数据根；零匹配失败，多匹配交由本地选择器。

验证：默认用户目录、非默认安装目录、多个数据盘、零/单/多账号、reparse、路径重叠和签名不匹配的合成测试全部覆盖；源码不得包含具体用户名或固定用户盘符。

## 任务 5：参数化验证器、进程和 VSS 边界

将正式 WeFlow 路径、安装根、快照根和恢复根从模块常量改为经验证合同参数。Node 验证器只接受启动器传入的、位于当前运行根下的规范路径；VSS helper 保持固定受保护 journal 根，但快照输出根来自已验证设置。

验证：跨根、相对路径、UNC、设备路径、reparse、大小写混淆、父子重叠和参数注入测试均失败关闭；正常合成验证保持通过。

## 任务 6：实现首次存储选择和本机设置

新增 `settings.py` 与 `storage_selection.py`。枚举固定 NTFS 卷，计算源数据、复制集、验证区和安全余量，排除源目录与正式程序/配置重叠路径，推荐空间最大的合格卷。用户确认后将规范路径写入 Local App Data 下的私有设置文件，并在每次刷新时重新验证。

验证：空间不足、非 NTFS、网络/可移动卷、卷身份变化、设置篡改、宽松 ACL 和路径重叠测试失败；单个合格卷与用户改选均通过。

## 任务 7：接入通用桌面刷新流程

入口只支持数据库刷新模式。首次运行完成发现和存储确认；后续运行加载并重验设置。保留 `START` 与 `CONFIRM <run-id>` 双确认、正常关闭、临时切换、提交、回滚、镜像事务和高级恢复命令。所有输出通过固定脱敏映射。

验证：合成端到端覆盖取消开始、预检失败、成功提交、拒绝确认、EOF、Ctrl+C、验证失败、临时切换异常、恢复待处理和第二次刷新。

## 任务 8：实现用户级单命令安装

创建根目录 `install.ps1`、包内 `scripts/Install-WeFlowChat.ps1` 与快捷方式包装器。安装器校验版本化 ZIP 的 SHA-256 后才执行归档内容，使用 Local App Data 暂存和原子升级，安装自带 Python 3.12/Node 24 运行时，创建固定无参数快捷方式并读回验证。VSS 信任根安装保持独立、边界明确的 UAC 操作。

验证：全新安装、重复安装、升级、哈希不符、归档穿越、损坏运行时、快捷方式篡改和升级回滚 Pester 测试通过；不修改系统 Python、Node、WeFlow 或 Weixin 安装目录。

## 任务 9：补齐许可证、隐私、安全和用户文档

编写 `README.md`、`LICENSE`、`PRIVACY.md`、`SECURITY.md` 和 `THIRD_PARTY_NOTICES.md`。README 中文优先并提供英文安装摘要，明确已初始化 WeFlow、支持版本、两个 UAC、手动刷新、未知版本停止、离线处理、无自动清理和非官方定位。

验证：文档链接、命令、文件名和许可证声明由测试检查；不得声称 OSI 开源、官方支持、自动刷新或任意版本兼容。

## 任务 10：建立 Windows CI 与 Release 构建

GitHub Actions 固定 Windows runner、Python 3.12 和 Node 24，依次运行 Python、Node、Pester、隐私/依赖扫描、`git diff --check`、合成端到端和 Release 清单验证。Release 工作流只从版本标签构建，固定依赖来源与哈希，生成 ZIP、SHA-256 和第三方许可证清单。

验证：普通 CI 不读取用户环境或真实软件；篡改任一依赖哈希、遗漏许可证、引入禁止文件或从脏树构建时失败。

## 任务 11：公开验收

在干净临时目录从提交重建；运行完整测试；扫描工作树、对象库、提交、Release ZIP 和解压结果；验证安装命令不使用 `Invoke-Expression`，归档校验发生在代码执行前。使用合成 WeFlow/Weixin 安装完成安装、刷新、提交、回滚和未知版本零写入验收。

验证：所有成功门禁通过，Git 状态干净，最终报告列出支持边界、测试计数、Release 哈希和零隐私发现。真实环境只执行只读预检，不自动上传仓库或创建 GitHub Release。

## 提交策略

每个任务形成一个可独立回退的提交；只暂存该任务文件。迁移提交与通用化提交分离，便于审计是否引入私人内容。任何测试失败、隐私发现或不明差异都在进入下一任务前修复。
