# weflow-chat 源码可见版设计

## 状态

本设计已由用户于 2026-08-09 分段确认。项目名称为 `weflow-chat`。

## 背景

现有刷新工具已经在一台 Windows 主机上完成真实聊天数据库刷新、只读快照、隔离验证、确认切换和失败回滚，但生产入口仍绑定单机账号、固定盘符、固定用户目录和历史诊断材料。直接复制现有仓库会泄露个人信息，也无法供其他用户可靠安装。

`weflow-chat` 使用全新仓库和全新 Git 历史，只精选迁移已经验证的刷新核心及其必要测试。它是源码可见的软件，不继承原仓库的提交、运行记录、私人设计文档或诊断产物。

## 目标

- 面向 Windows 10/11 x64 用户。
- 用户已经安装并至少成功初始化过 WeFlow，WeFlow 已持有可用的 `safe:` 密钥信封。
- 用户通过一条版本固定的 PowerShell 命令完成安装。
- 安装后通过桌面快捷方式执行人工聊天数据库刷新。
- 刷新过程不上传聊天、账号、路径、头像、媒体、密钥或诊断信息。
- 已验证的微信与 WeFlow 运行时才能执行正式配置切换。
- 任何失败均保持旧数据可恢复，并提供 `status`、`resume` 和 `rollback` 恢复入口。

## 非目标

- 不为从未初始化过 WeFlow 的用户提取或导入首次密钥。
- 不扫描微信进程内存，不迁移原项目的密钥诊断脚本。
- 不下载、补抓或重新发布聊天附件、头像和朋友圈媒体。
- 不支持 macOS、Linux、32 位 Windows 或 ARM Windows。
- 不自动删除历史快照，不提供自动计划刷新。
- 不绕过未知版本或失败的安全检查。
- 第一版不提供图形化配置程序；普通入口为桌面快捷方式和受控控制台向导。

## 总体架构

项目由六个边界清晰的组件组成：

1. **版本固定安装器**：下载 Release、校验 SHA-256、安装用户级文件并创建快捷方式。
2. **主机发现器**：通过 Windows 已知目录、已安装程序信息、签名后的可执行文件和 WeFlow 本机配置发现环境。
3. **预检器**：验证版本、路径、进程、磁盘格式、空间、账号唯一性和历史事务状态。
4. **刷新状态机**：创建只读 VSS 快照、复制数据库、持久化双份事务、执行临时切换并提交或回滚。
5. **隔离验证器**：在复制的 WeFlow 运行时和隔离 profile 中验证数据库结构、统计、覆盖率和可打开性。
6. **恢复工具**：只接受规范 UUID，读取镜像事务并执行状态查看、继续或回滚。

组件之间只传递经过验证的路径对象、不可变运行记录和脱敏结果。主机发现不直接修改正式配置；只有刷新状态机在完成备份和持久事务后才能进入临时切换。

## 新仓库边界

新仓库使用允许清单精选迁移，不复制原仓库目录树后再删除。允许迁移的内容仅包括：

- 数据库只读复制、清单、原子写入、事务和回滚核心；
- VSS helper 及其权限边界；
- 隔离验证器中数据库验证必需的 Python 和 Node 代码；
- 桌面刷新入口及安装器；
- 与上述模块一一对应的合成测试。

明确排除：

- 真实账号 ID、用户名、绝对用户目录、固定 E/F 盘路径和历史运行 ID；
- 原仓库 Git 历史、私人设计/实施文档和恢复交接材料；
- 真实数据库、配置、缓存、媒体、日志、事务、信任回执和哈希证据；
- 内存扫描、首次密钥提取及内部诊断脚本；
- `__pycache__`、测试缓存、Node 依赖目录、构建产物和本机设置。

## 安装与升级

Release 为 Windows x64 版本化 ZIP，并同时发布 SHA-256 文件。Release 页面提供一条版本固定的 PowerShell 命令。该命令先下载 ZIP 和校验值，在执行 ZIP 内任何代码前完成哈希比较，再解压到用户级暂存目录并调用包内安装器。

正式安装目录为 Windows Local App Data 已知目录下的 `WeFlowChat`，不用硬编码用户名。安装采用同卷暂存和原子目录切换；升级失败时继续使用旧版本。安装器只创建或替换：

- 用户级 `WeFlowChat` 安装目录；
- 用户桌面的 `刷新 WeFlow 聊天记录` 快捷方式；
- 用户级设置目录及最小必要文件。

Release 自带固定版本的 Python 3.12 与 Node 24 用户级运行环境，用户无需预装开发工具。构建过程固定上游下载地址和哈希，并在 `THIRD_PARTY_NOTICES.md` 收录运行时及依赖许可证。安装阶段允许联网；刷新阶段不发起网络请求。

安装器不修改系统 Python、系统 Node、微信安装目录或 WeFlow 安装目录。VSS 信任根仍是一次性的独立 UAC 操作，日常刷新只为精确创建和删除本工具拥有的影子副本请求提权。

## 主机与账号发现

主机发现器按以下顺序工作：

1. 使用 Windows Known Folder API 定位 Local App Data、Roaming App Data、Documents 和 Desktop。
2. 从已安装程序记录和规范安装位置发现 WeFlow；必须验证目标是普通文件、路径链无 reparse point，并匹配受支持运行时哈希。
3. 从正在运行的 Weixin 进程或已安装程序记录发现 Weixin；必须验证 x64、Authenticode 有效、腾讯签名主体、证书身份、DLL 版本和 DLL 哈希。
4. 从 WeFlow 本机配置读取账号选择器和已有 `safe:` 信封，只在内存中保留所需字段。
5. 只读枚举 Weixin 已登记的数据根及结构合法的 `xwechat_files` 账号目录，并与 WeFlow 账号选择器匹配。
6. 恰好一个匹配时自动采用；多个匹配时在本地显示选择向导；没有可靠匹配时允许用户选择账号目录，随后执行完整结构和边界验证。

账号 ID、完整路径和信封内容不得进入控制台摘要、日志、崩溃报告或测试快照。持久设置可以保存规范路径，但文件 ACL 仅允许当前用户和 SYSTEM，且设置文件永不进入仓库。

## 快照存储选择

首次刷新枚举本机固定 NTFS 卷，拒绝网络盘、可移动盘、非 NTFS 卷、reparse 目标以及与源账号、正式 WeFlow、正式配置或安装目录重叠的路径。

预检先稳定枚举源数据库文件数与字节数，再按复制集、隔离验证和安全余量计算所需空间。向用户推荐满足空间要求且剩余空间最大的合格卷，默认目录名为 `WeFlowChatData`。用户必须确认后才创建目录。

确认结果保存在用户级设置中。以后刷新沿用该目录，但每次仍重新验证卷身份、NTFS、路径边界、ACL 和剩余空间。工具不自动挑选新盘，也不自动删除旧快照。

## 版本信任策略

正式写入能力采用哈希定义的允许清单，而不是仅比较版本字符串。

- 微信身份必须同时匹配架构、版本、DLL SHA-256、Authenticode 状态和签名身份。
- WeFlow 必须匹配完整的运行时文件哈希、应用结构锚点、WCDB 方法集合和补丁入口。
- 第一版只迁移已经通过现有合成测试和真实只读验证的身份记录。
- 新版本只能通过单独的代码审查、合成验证、只读试运行和新 Release 加入允许清单。
- 未知但签名合法的版本只生成脱敏只读兼容报告并停止；不创建正式配置备份、不替换配置、不建立本地信任捷径。
- 签名、架构或身份异常的版本直接拒绝。

## 刷新数据流

1. 用户启动桌面快捷方式，入口拒绝参数注入并加载用户级固定安装。
2. 预检要求 Weixin 环境可验证、WeFlow 已正常退出、无残留验证器、无未完成或分叉事务。
3. 向用户显示仅含计数、空间和状态码的脱敏摘要；只有输入完全一致的 `START` 才继续。
4. 分配新的 UUID 和不可变运行目录，先写入双份事务起点。
5. 通过受信 VSS helper 为精确源卷创建本工具拥有的只读影子副本。
6. 从影子副本复制数据库，生成文件清单和哈希，并在复制后重新验证源身份与稳定计数。
7. 在复制的 WeFlow 运行时、隔离 profile 和隔离输出目录中验证数据库。验证覆盖 session、message、media、contact、hardlink、migrate 等已知角色，并比较 schema、aggregate 和 database-coverage 指纹。
8. 删除精确影子副本并记录已删除 journal；不允许采用或删除非本工具创建的影子副本。
9. 备份正式 WeFlow 配置与受影响缓存，双份事务持久化后进行临时配置切换，使正式 WeFlow 指向新验证副本。
10. 启动正式 WeFlow，让用户检查最新聊天和时间。只有输入完全一致的 `CONFIRM <run-id>` 才提交事务。
11. 拒绝确认、EOF、Ctrl+C、异常或校验变化均恢复旧配置并记录回滚。提交前后均不修改微信源数据库。

第一版使用数据库刷新模式，不导入旧媒体、不补抓附件，也不改变已有共享媒体仓库和朋友圈缓存策略。

## 故障与恢复

状态机的每次转换都使用规范 JSON、同卷临时文件、文件刷新和原子替换，同时写入快照根与配置同卷恢复根。两份事务必须具有相同序号和 SHA-256；缺失、降级或分叉时所有变更命令失败关闭。

错误处理遵循以下规则：

- 不强制结束 Weixin 或 WeFlow；正常关闭超时即停止。
- 不吞掉未知异常，不自动重试可能产生写入的步骤。
- 临时切换之后的失败优先恢复旧配置；无法证明恢复完成时标记 `RECOVERY_PENDING`。
- `status` 为只读；`resume` 和 `rollback` 使用同一用户级互斥锁并只作用于精确运行 ID。
- 任何恢复命令都不猜测哪份分叉事务正确，也不自动删除证据。
- 用户可在旧版本保持可用的前提下处理失败运行。

## 隐私与日志

普通输出只允许：布尔状态、固定原因码、文件/字节计数、空间需求、版本支持状态、运行 UUID 和事务阶段。日志不得包含：

- 账号 ID、联系人、消息、时间线内容或媒体名称；
- 完整本机路径、用户名、计算机名、PID 命令行或环境变量；
- 密钥信封、解密密钥、图片密钥或可逆凭据；
- 真实数据库片段、配置内容、缓存内容或媒体内容。

项目不包含遥测、自动更新检查、错误上传或外部 API。只有用户主动执行安装/升级命令时访问 Release 下载地址。

## 测试与发布门禁

持续集成只在 GitHub 托管的 Windows 环境使用合成数据，包含：

- Python 单元与集成测试；
- Node 24 验证器测试；
- PowerShell 安装器与 VSS helper 合同测试；
- 临时 Known Folder、多个账号、无账号、空间不足和路径重叠测试；
- 完整合成刷新、确认提交、拒绝回滚、异常恢复和镜像分叉测试；
- 未知微信/WeFlow 版本零正式写入测试；
- 刷新阶段网络调用为零的测试；
- Release ZIP 可复现清单、SHA-256 和第三方许可证检查。

隐私门禁扫描工作树、暂存区和完整 Git 历史，拒绝：

- 用户目录字面量、个人账号 ID、固定个人盘符或历史运行 UUID；
- 数据库、媒体、配置、缓存、事务、日志、密钥和信任回执文件；
- 高熵凭据、访问令牌、私钥和未脱敏测试夹具；
- 原项目路径、私人设计文档标题和诊断输出标记。

发布只能从干净提交创建；所有测试、隐私扫描、许可证检查和 `git diff --check` 必须通过。

## 验收标准

项目满足以下全部条件才达到“可以公开”：

1. 新仓库没有原 Git 历史，隐私扫描对工作树和历史均为零发现。
2. 全新 Windows 10/11 x64 用户无需系统 Python/Node，即可通过一条版本固定 PowerShell 命令安装并得到桌面快捷方式。
3. 用户已初始化 WeFlow 且版本受支持时，可以完成合成端到端刷新、人工确认、提交和下一次刷新。
4. 拒绝确认或任一注入故障后，旧配置逐字节恢复，未修改微信源数据。
5. 未知或不受信版本只产生脱敏只读结果，正式配置写入计数为零。
6. 刷新阶段即使网络不可用也能完成，且代码不会尝试联网。
7. 多账号、非默认安装目录和非默认数据盘由发现与本地选择处理，不依赖用户名或固定盘符。
8. README、限制性 LICENSE、隐私、安全和第三方许可证文档完整，并明确非官方与源码可见定位。

## 实施顺序

实施按风险递增拆分：先建立公开边界和隐私门禁，再迁移纯核心与合成测试；随后实现主机发现和存储选择；再接入用户级运行时与安装器；最后执行合成端到端、受支持真实环境只读验证和 Release 构建。任何阶段不得为了通过测试而放宽路径、版本、签名、事务镜像或回滚校验。
